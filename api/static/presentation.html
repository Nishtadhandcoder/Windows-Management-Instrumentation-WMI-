Good morning everyone. Today I'm presenting the Enterprise WMI Telemetry & Persistence Engine. It provides zero-overhead, agentless hardware and software telemetry from Windows endpoints, guarantees zero-loss persistence with MongoDB and local cache, and visualizes live system health in a modern dashboard.
The Business Problem

Legacy Infrastructure Monitoring Bottlenecks

Why traditional IT monitoring architectures introduce security and operational risks.

Traditional Bottleneck Operational Risk Our Architectural Solution
Heavy Third-Party Agents CPU/RAM bloat, patching cycles, security vulnerabilities Native Agentless WMI: Zero endpoint software installations.
Disconnected Data Silos Inconsistent audits between hardware, users, and software Unified Data Contract: Pydantic CompleteSystemSnapshot schema.
Central DB Failure Risk Lost telemetry snapshots during database maintenance Resilience Mode: Seamless buffering to local disk cache.
Manual Audit Cadence Compliance reports are stale upon generation Continuous Daemon: Autonomous 60s background probe.
Slide 02 / 08 Infrastructure Risk Assessment
In enterprise IT, heavy monitoring agents increase endpoint vulnerability and resource consumption. Furthermore, if the central logging server drops, critical telemetry is lost. Our solution addresses this via native WMI and intelligent offline caching.
System Design

Four-Tier Production Architecture

Modular pipeline separating acquisition, validation, storage, and interfaces.

1️⃣
Collection Engine
Thread-safe COM manager querying 8 domain-specific collectors (OS, Disks, Network, Services, Registry).
2️⃣
Data Validation
Strongly typed Pydantic models enforcing schema integrity, datetime parsing, and username length computation.
3️⃣
Dual Persistence
MongoDB collection indexing with automatic, zero-crash fallback to local JSON snapshots.
Slide 03 / 08 Modular Tiered Architecture
Our architecture cleanly separates concerns into 4 tiers: Collection, Validation, Dual Persistence, and Consumption. This guarantees thread safety and allows downstream systems to integrate via REST API or CLI effortlessly.

Reliability Engineering

Dual Storage Engine & Offline Resilience

Eliminating single points of failure in enterprise telemetry pipelines.

🍃
Primary: MongoDB
Time-series JSON snapshot collection with indexing on machine name, snapshot ID, and timestamp.
🛡️
Fallback: Local Cache
Automatic write-buffering to data/snapshots/ whenever MongoDB is offline or undergoing maintenance.
🔄
Zero-Crash Philosophy
Neither the FastAPI server nor the background scheduler crash when the database drops connection.
Slide 05 / 08 Storage Fault-Tolerance
Data integrity is our top priority. If MongoDB drops connection, the client manager intercepts the timeout and engages operational resilience mode, buffering snapshots to disk without dropping a single audit cycle.
